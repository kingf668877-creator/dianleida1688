OZON 搜索词跨语言匹配规则

基于 AI 输出的三语搜索词分析结果（中/俄/英），对 OZON 商品标题进行五层分层匹配与排序。匹配逻辑由后端代码控制，AI 只负责输出分析结果。

一、核心思路

一句话概括：AI 把用户搜索词拆解为三语关键词结构，后端拿这个结构对商品标题做五层逐层宽松匹配，命中层级越高的排越前面，同一层内按命中语言数和修饰词命中数排序。

设计原则

  • 结果最多、相关度高的排前面：从精准到兜底五层渐进，宁可多召回不错杀
  • 跨语言 OR 匹配：商品标题可能是俄文、中文、英文或三语混拼，任一语言命中即算匹配
  • 匹配排序由后端控制：AI 提示词不包含任何匹配规则，只输出三语分析 JSON
  • 同语言加权：标题中同一语言命中的关键词越多，相关度越高（可选加分项）
L1
必含词[0]（任意语言）＋全部修饰词（每个修饰词任意语言命中）→ 最精准，排最前
L2
某个扩展词完整命中（三语中任一完整短语出现在标题）→ 精准
L3
必含词[0]（任意语言）＋某个扩展词的全部拆词（每个拆词任意语言命中）→ 宽松
L4
必含词[0]（任意语言）＋部分修饰词（至少1个修饰词任意语言命中）→ 宽松
L5
仅必含词[0]（任意语言）命中 → 兜底召回，排最后
关键概念：跨语言 OR每个关键词在 AI 输出中都有 {zh, ru, en} 三个版本。匹配时，只要三个版本中任意一个出现在商品标题中，就算该关键词命中。

二、AI 输出数据结构

后端接收到的 AI 分析结果为以下 JSON 结构。每个关键词字段都是三语对象，匹配时对三语做 OR 判断。

{
  "coreProduct": {"zh":"外套", "ru":"пальто", "en":"coat"},
  "modifiers": {
    "style": [{"zh":"休闲", "ru":"повседневное", "en":"casual"}],
    "material": [],
    "crowd": [{"zh":"男士", "ru":"мужское", "en":"men's"}],
    "scene": [],
    "brand": []
  },
  "expandedKeywords": [
    {"zh":"男士休闲外套", "ru":"мужское повседневное пальто", "en":"men's casual coat"}
  ],
  "expandedTokenGroups": [
    {"zh":{"tokens":["男士","休闲","外套"]}, "ru":{"tokens":["мужское","повседневное","пальто"]}, "en":{"tokens":["men's","casual","coat"]}}
  ],
  "requiredKeywords": [{"zh":"外套", "ru":"пальто", "en":"coat"}]
}
字段类型匹配中的角色说明
coreProductTrilingual参考核心品类词，供理解用，实际匹配用 requiredKeywords[0]
modifiersTrilingual[]修饰词style/material/crowd/scene/brand 合并参与匹配
expandedKeywordsTrilingual[]L2 完整匹配任一项的任一语言完整出现在标题即命中 L2
expandedTokenGroupsTokenGroup[]L3 拆词匹配任一语言的 tokens 全部命中即满足 L3 的扩展词条件
requiredKeywordsTrilingual[]必含词[0] 是核心必含词，五层匹配都离不开它
requiredKeywords[0] 铁律必含词第一个是纯核心品类词（如“外套”而非“男士外套”）。匹配从 L1 到 L5 都以 requiredKeywords[0] 为基础锚点。

三、跨语言匹配机制

3.1 三语 OR 匹配

matchKeyword(title, kw): return contains(title, normalize(kw.zh)) OR contains(title, normalize(kw.ru)) OR contains(title, normalize(kw.en))

只要三个语言版本中任意一个在标题中出现，该关键词即算命中。空字符串跳过。

3.2 三语短语完整匹配（L2 用）

matchExpandedKeyword(title, ek): return contains(title, normalize(ek.zh)) OR contains(title, normalize(ek.ru)) OR contains(title, normalize(ek.en))

L2 是完整短语匹配，不是拆词匹配。

3.3 三语拆词全部命中（L3 用）

matchTokenGroup(title, group): zh_all = ALL(group.zh.tokens, t => contains(title, normalize(t))) ru_all = ALL(group.ru.tokens, t => contains(title, normalize(t))) en_all = ALL(group.en.tokens, t => contains(title, normalize(t))) return zh_all OR ru_all OR en_all

任一语言版本的所有拆词都出现在标题中（不需要连续），该 tokenGroup 即算命中。

四、五层匹配规则详解

每个商品标题按 L1 → L2 → L3 → L4 → L5 顺序依次判断，命中最高层即停止。

必含词[0] + 全部修饰词 排名最高

matchKeyword(title, requiredKeywords[0]) AND ALL(modifiers, m => matchKeyword(title, m))

某个扩展词完整命中 排名第二

ANY(expandedKeywords, ek => matchExpandedKeyword(title, ek))

必含词[0] + 某个扩展词全部拆词 排名第三

matchKeyword(title, requiredKeywords[0]) AND ANY(expandedTokenGroups, g => matchTokenGroup(title, g))

必含词[0] + 部分修饰词 排名第四

matchKeyword(title, requiredKeywords[0]) AND ANY(modifiers, m => matchKeyword(title, m))

仅必含词[0]命中 排名最后

matchKeyword(title, requiredKeywords[0])

五、文本归一化规则

处理项适用语言规则示例
大小写归一EN/RU统一转小写Coat → coat
ё → еRU俄语字母 ё 统一替换为 еёж → еж
变音符去除ENNFKD 分解后去除组合变音符号café → cafe
标点去除全部去除常见标点符号，替换为空格men's → mens
多空格压缩全部连续空白字符合并men's casual → mens casual
def normalize_text(text: str) -> str:
    if not text:
        return ""
    text = text.lower().replace("ё", "е")
    text = unicodedata.normalize("NFKD", text)
    text = "".join(c for c in text if not unicodedata.combining(c))
    text = unicodedata.normalize("NFKC", text)
    text = re.sub(r"[^\w\s\u4e00-\u9fff]", " ", text, flags=re.UNICODE)
    return re.sub(r"\s+", " ", text).strip()

六、完整匹配示例

以搜索词“男士休闲外套”为例，展示不同商品标题命中的层级。

模拟 OZON 商品标题
✓“Мужское повседневное пальто осеннее”
命中 пальто + мужское + повседневное（全部修饰词）L1
✓“Men's casual coat autumn winter jacket”
完整短语 mens casual coat 命中扩展词L2
✓“男士外套 休闲 秋冬款”
必含词“外套”命中，且 tokens 男士/休闲/外套 全中L3
✓“Пальто мужское осеннее”
пальто 命中 + мужское 命中，缺 повседневноеL4

关键结论跨语言匹配不要求标题和关键词用同一种语言。每个关键词独立做三语 OR 判断，不同关键词可以命中不同语言。

七、边界情况处理

7.1 空值处理

  • requiredKeywords 为空数组 → 该搜索词无法匹配，返回空结果
  • 某个关键词的 zh/ru/en 中有空字符串 → 该语言版本跳过
  • 三个语言全为空 → 该关键词视为不存在
  • modifiers 全空 → L1 条件等价于 L5
  • expandedKeywords 为空 → L2/L3 自动跳过

7.2 品牌词处理

顶层 brand 和 modifiers.brand 数组合并后统一作为修饰词参与匹配。品牌名通常保留原文。

7.3 复合产品名

如“手机壳”“麻将包”等复合产品名，AI 会将完整产品名作为 requiredKeywords[0]，后端按普通关键词处理即可。

7.4 俄语词形变化

当前方案先做子串包含匹配，不做词形还原。如果后续俄语漏匹配严重，可考虑接入俄语词形还原或让 AI 输出多个俄语变体。

7.5 性能考虑

  • 先用 requiredKeywords[0] 的三语版本做粗筛，快速排除不相关商品。
  • 粗筛后的候选集再执行完整五层判断。
  • 商品库量大时建议用 Elasticsearch / OpenSearch 的 multi-match + bool query 实现。

八、完整伪代码

def match_keyword(title, kw):
    return contains(title, normalize(kw.get("zh", ""))) \
        or contains(title, normalize(kw.get("ru", ""))) \
        or contains(title, normalize(kw.get("en", "")))

def match_token_group(title, group):
    for lang in ["zh", "ru", "en"]:
        tokens = group.get(lang, {}).get("tokens", [])
        if tokens and all(contains(title, normalize(t)) for t in tokens):
            return True
    return False

def classify_layer(title_norm, analysis):
    modifiers = collect_all_modifiers(analysis)
    required = analysis["requiredKeywords"]

    def required_hit():
        return all(match_keyword(title_norm, rk) for rk in required)

    if required_hit() and all(match_keyword(title_norm, m) for m in modifiers):
        return 1
    if any(match_keyword(title_norm, ek) for ek in analysis["expandedKeywords"]):
        return 2
    if required_hit() and any(match_token_group(title_norm, g) for g in analysis["expandedTokenGroups"]):
        return 3
    if required_hit() and any(match_keyword(title_norm, m) for m in modifiers):
        return 4
    if required_hit():
        return 5
    return 0
